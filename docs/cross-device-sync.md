# 跨设备同步设计

## 目标

同一 WzzScrm 主账号在家里电脑、公司电脑、Mac 和 Windows 上登录后，看到同一个客户工作区；同一主账号创建的客服子账号也共享业务数据。不同主账号之间必须严格隔离。

## 数据边界

服务器以 `基础租户 + 主账号 ID` 作为客户工作区。聊天会话、消息、媒体、账号目录、工单、分享链接、重粉库和自动回复幂等记录都写入该工作区。个人已读位置按登录用户保存，因此同一账号的两台电脑共享已读状态，不同客服互不影响。

桌面端只保留可重建的本地缓存。启动或登录时先从服务器恢复全量历史，再每 5 秒拉取增量；本机发生消息或客户资料变更后会在约 350 毫秒内主动同步。游标由服务端更新时间和稳定业务 ID 组成，避免同一毫秒多条消息漏同步。

## 会同步的内容

- 会话、文字与媒体消息、翻译结果
- 客户昵称、公开 ID、头像、备注、语言、置顶、静音、自动回复开关
- 已读位置
- 平台账号目录、备注与默认客户语言
- 工单、分享链接、粉丝数据开关和重粉库
- 可选的界面、翻译、通知和快捷回复等个人偏好

## 不复制到另一台电脑的内容

平台登录凭证、平台会话、代理地址、代理密码和设备指纹不进入云端。WhatsApp、LINE、Telegram、KakaoTalk 在新电脑上恢复账号入口后，需要为该电脑配置代理并重新扫码/授权一次；完成后历史聊天立即与服务器主库合并。由服务器托管 OAuth 的平台可以自动恢复授权账号。

这样可以同时满足跨设备恢复和网络隔离：不会把 A 电脑的代理、Cookie 或设备身份复制成 B 电脑的指纹，也不会在代理断开时回落本机直连。

## 并发与冲突

- 消息按平台稳定消息 ID 幂等写入，多台电脑同时收到同一消息不会重复入库。
- 同一来信的 AI 自动回复由服务器抢占，同一工作区只允许一台电脑执行。
- 会话资料采用服务端更新时间的后写生效；删除平台账号使用墓碑，离线旧电脑不会把它重新创建。
- 媒体文件先查缺再上传，新电脑按媒体 ID 下载并缓存。

## 验收矩阵

1. Mac 工作后退出，在 Windows 登录同一 WzzScrm 账号：历史会话、消息、客户资料、工单和账号目录恢复。
2. 两台 Windows 或 Mac + Windows 同时在线：任一端收到/发送的消息在另一端出现，已读状态同步，自动回复不重复。
3. 新电脑未配置某平台代理：可以看到服务器历史，但平台连接保持离线且禁止本机直连；配置代理并完成平台授权后恢复收发。
4. 两个不同主账号登录不同设备：任何会话、媒体、工单与账号目录均互不可见。
